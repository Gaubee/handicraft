# 贴钻工作台架构裁定

本文件记录 2026-09-29 前后台分离讨论的项目级裁定，完整理由、源码依据和 Vision 验收门见 `/tmp/codex-arch-split-review.md`。以下是目标约束，不表示代码已实现。

## 工作区边界

- 前后台是同 SPA、同 daemon 的角色与工作流分层；后台使用 `#/admin/{tab}` hash 路由，前台默认保持 Agent。
- 客户端 admin 守卫只负责提示与跳转；每个后台 RPC 均须服务端 `requireAdmin`。
- 首次管理员由 `.env ADMIN_*` 幂等建号；不开放公开注册。多角色新安装默认关闭匿名访问，显式设置可覆盖。
- 禁用账号阻断后续读写和刷新/新登录、保留数据；每次 RPC 按数据库当前状态校验，不信任 JWT 内的角色快照。
- 管理导航按账号、资源、知识库、设置组织；模型/图像设置进后台。装饰钻管理进后台，Agent MCP 消费不变。
- 素材库必须先有 daemon 真源、owner/shared 语义和可核验的 IndexedDB 迁移；前台继续保留本人素材与会话附件入口。
- 现“仓储管理”实为用户归属的组合/套装，不是实物库存。本波称“组合库/套装库”并明确归属；不虚构库存数量和出入库。

## Agent 图片与知识

- 图片聊天使用结构化 `BlobRef[]`，会话取得引用时校验 owner 并原子记账；dsh 收到原生图像内容块。禁止将绝对磁盘路径拼入提示词或为 session 创建 taskRoot 硬链接。
- 图片原图/缩略图读取必须鉴权并校验资源归属；BlobRef 不等同于访问授权。
- 知识库采用 Markdown 文件、Git 修订、后台 CRUD 和 Agent MCP 读取。Agent 写须经持久提案/审批；授权桥未完成时保持只读。
- `scene.analyze` 是贴钻结构分析工具，不能替代通用图片会话输入；所有视觉模型调用最终须遵循后台模型路由。

## 实施顺序

1. 冻结角色、归属、附件生命周期和知识写授权契约。
2. 登录/后台身份与服务端管理 RPC，迁移模型设置。
3. 图片上传、会话归属、原图/缩略图、原生多模态输入与历史回放。
4. 知识库管理和 MCP 读写授权。
5. 钻库/组合后台化，素材服务化与 IndexedDB 迁移核验。
6. 全部实现门通过后，Vision 子代理在隔离实例用 ego-browser 完成后台配置到图片演练和 PNG 导出。
