## Personas（收敛为 3）

### P1 王老板 · 接单者（novice→中间）
经营贴钻工坊。客户在微信里发来一张设计图问「这个能做吗？多少钱？」。他不
知道什么是 manifest/BOM/lint，只用鼠标，忍受不了超过三步的操作和任何看不懂
的词。**他的商业动作：报价 → 接单 → 交付。**

### P2 排钻师 · 操作者（expert）
天天排钻的熟练工（也可能就是王老板自己干）。对密度、图层、边界、钻的型号
极其敏感，要肌肉记忆级的效率：键盘、批量、双击直达。**他的生产动作：修图 →
排钻 → 导出三件套发厂。**

### P3 管家 · 管理员（Owner 本人/工坊 IT）
维护材料市场（新供应商钻卡入库）、账号、模型配置、知识库。服务全工坊：
**材料上架越快，接单越快。**

## 每界面一 novice 一 expert（故事即验收）

### 前台 · 会话（接单面）
- **N1（王老板，报价闭环）**：客户发来雪人图 → 我把图拖进对话，挑一个常用
  材料组合（「圣诞系列」）→ AI 排完直接告诉我：用了哪些钻、每样多少颗、
  总数多少 → 我截图回微信报价。
  **验收**：拖图→见到总钻数 ≤3 步且全程无技术词汇；总数必须一眼可见（不是
  藏在导出件里）。
- **E1（排钻师，精修闭环）**：排完不满意左手密度 → 打开工作台 → 点左手改
  密度看钻数实时变 → 导出三件套。
  **验收**：会话→工作台≤2 击；改密度→钻数反馈即时；导出一击确认。

### 前台 · 工作台（生产面）〔treeView goal 五条在此线〕
- **E2（排钻师）**：图层树就是我的手——「小丑」下面直接是左手/右手（不是
  「小丑·部分1」这种机器语言）；改一个区块密度，颗数与我预期的心算一致
  （2.3颗/cm² × 面积）；缩略图要看得清也得知道它在画布哪里。
- **N2（王老板偶尔进来）**：只看总览——整体效果+总颗数，不迷路。

### 后台 · 资源管理（管家面）
- **N3（管家，上架闭环）**：新钻卡（CDR/图/CSV）→ 一个入口导入 → 材料市场
  全工坊可用，贴图齐全不缺。
  **验收**：不跑命令行；缺图如实告知缺哪些怎么补。
- **E3（管家，盘点）**：哪个组合被哪些单在用、任务历史回放、异常（缺图/
  失败）一眼扫出。

### 后台 · 设置/账号（管家面）
- **N4**：配一次模型/账号，忘了再来能找到；改完即生效不用重启。

## 两天需求的根因映射（为什么提）

| Owner 指令 | 根因（他要什么） |
|---|---|
| 合并面板+组合=分组 | 心智模型统一：组合不是独立世界，是材料的另一种打开方式 |
| 材料市场/我的材料改名 | 内外之分：市场是「行业有什么」，我的是「我选了什么」——故事骨架 |
| 我的材料三分区+废弃 IDB+「讲故事」元指令 | 产品要按「备料→组套→开工→归档」叙事闭环，不是功能堆叠 |
| 快速开始+拖拽 | N1 的前三步零门槛：打开就会用 |
| chat 抄作业 | 对话面是 P1 的主战场，zhumo 证明了「少即是多」的成熟度 |
| 预览 80%/贴图补全/92 升级 | 材料的「卖相」——看不清钻就等于没有钻（P1 选料靠眼睛） |
| treeView 五条 | E2 的手感：结构语言/密度心算/抠图忠实/缩略图双模/控件不打架 |
| 「点到为止」批评 | 每个功能都存在≠故事走得通——要用上面的 N/E 验收逐环实测 |

## 沙盒原则（每轮打磨的放置法）

- P1 的高频 20%：传图→选组合→看总数→（满意）导出——占直接视觉空间大头。
- P2 的快捷：工作台直达、密度即时反馈、批量——侧栏/快捷键/深入口。
- 其余一切收进深入口（Dialog/抽屉/折叠）——**宁可藏，不可摊**。
