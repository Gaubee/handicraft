# add-flat-aux-segmentation（参考图层——Owner 定名 2026-10-04）

## 为什么

sam-playbook iter-5 A/B 实验（Codex 终裁 9.1 vs 9.0，`experiments/sam-playbook-20261004/iter-5-flat-ab/`）证实：**扁平化参考图层作为分件输入显著简化 SAM 分件**（一次成树零修树/非默认阈值 20→0/中袍掩膜 68×/六星 fill 52.4% 历轮最高）。Owner 已定产品方向：

> 流程里发现原图不是扁平化风格 → 不直接用原图抠图，先将原图转化成「参考图层」（Owner 冻结提示词，见 iter-5-flat-ab/owner-flatten-prompt.md）→ 全层面抠图面向参考图层 → 导出时钻布局+**原图**（参考图层不显示）。

## 是什么（Codex A/B 终裁最小范围三条——设计骨架）

1. **四图引用分离**：原图 / 参考图层 / scene-analysis 降采样图 / 树掩膜源图——各自显式引用+坐标变换关系；**修 P1 树编辑锚点**（`tree.ts:108` 只取最新 scene-analysis 的 imageBlobRef → reparent/refine/merge/rename 应用与树匹配的掩膜源图引用；保留 `tree-persist.ts:169` 尺寸保护，禁止放宽绕过）；补「1280 树+500 分析图」定向回归。
2. **参考图层几何一致性门**：生成参考图层后校验轮廓几何一致性（掩膜可一一映射回原图才继续；不一致→回退原图流程或显式变换）；**最终导出必须引用原图**，布局落点与原图轮廓对齐检查（同尺寸≠同几何——OpenAI 重绘会微变轮廓，A/B 已实证羽翼/发冠/袍褶有变）。
3. **scene-analysis 稳健性+策略冻结**：输出规模与重试预算有界（iter-5 三连败=thinking 吃满预算+JSON 截断，供应商/预算问题非图片问题）；保留注入兜底；密度/点缀风格写成明确选项或默认规则（不再让策略 LLM 自行决定满铺 vs 点缀）；部件级钻数从最终 layout 复核（iter-5 终报数字沿用 v2 与 v4 终局不符的教训）。

## 触发面（风格检测）

流程入口检测原图是否扁平风格（低梯度/平坦色域占比等可计算判据 or VLM 判定——design 时定）；非扁平→走参考图层链路；扁平→直接原图。

## 参考图层生成能力

需 image-edit 生成通道（Owner 提示词冻结逐字使用）。候选：接入 OpenAI image edit（Owner 本轮用的）或产线现有 LLM 网关的多模态编辑能力——design 时选型（成本/保轮廓质量/本地化）。

## 不做什么

- 不改已验收的 add-vision-pipeline-v2 掩膜语义/账本/质量门
- 不动 SAM 服务面
- 归因边界如实：A/B 证明的是「这类扁平参考图层输入」的整体效果（含重绘几何变化），非纯「扁平化」单变量

## 验收口径（草案）

- 非扁平原图 → 自动生成参考图层 → 分件在参考图层上 → 导出产物 source/render 基于原图（混合预览可对照）
- 1280 树+500 分析图定向回归绿；reparent/refine 在分离引用下不再触发尺寸拒
- 参考图层几何一致性门：构造轮廓漂移用例→回退原图路径
- 旗舰图三天使全链重跑：验收五条全 PASS 且导出基图=原图
