# add-sam-playbook

## 为什么

SAM 分件的能力面远没吃满。Owner 实战观察（2026-10-04）：对三天使图说「三个天使」始终只抠出两个；改用「background」剔除背景+反选反而拿到三个天使+星星+花篮——**提示词策略需要知识库辅助决策**，且桥协议里现成的能力（多实例枚举/负例框/纯 box）与点提示（processor 无 API 但可微框近似）都没有暴露给 Agent 与工作台。要把 SAM 用好，需要「能力面升级 + 知识库 + 实战迭代闭环」三件套同时推进。

## 是什么（Owner 指令原文拆解）

1. **玩法①②③④落地**（⑤VLM analyze 明确不做）：
   - ① 多实例枚举：同款全抠、逐实例成层（逐星/逐花的产品短板解）
   - ② 负例框 boxNegative：排除区域（泄漏类问题的指令级解）
   - ③ 纯 box 几何抠图：框选即抠，不赌语义
   - ④ 点提示：正/负点击（spike 定方案：微框近似 vs 服务改造）
2. **MCP 工具升级**：新参数+用法指引进工具描述（Agent 唯一自学渠道）
3. **抠图（任务详情）Dialog 升级**：负框绘制/纯框模式/实例枚举结果
4. **skills/知识库升级**：网上研究官方提示词语料/例子 → 知识库新组「SAM 提示词策略」+ Owner 战例条目
5. **Agent 实战迭代闭环**：升级后 Agent 用新 MCP 工具跑三天使分件 → **Codex 审查结果** → 调整 skills/知识库 → Agent 重试 → 循环**直到 Codex 满意**；每轮开新会话、结果全部存档不覆盖（Owner 要看完整升级过程）

## 不做什么

- VLM analyze（Owner 裁定没必要）
- 不动质量门/预览回流/账本语义（add-vision-pipeline-v2 已验收面）
- 迭代循环期间不改管线代码（Codex 判定代码问题→出循环单独修复再重启循环）

## 验收口径（Owner 定义）

- ①②③④四玩法在 MCP 工具与 Dialog 双面可用（schema 测试+Dialog 走查）
- 知识库「SAM 提示词策略」组成型（研究条目带来源+Owner 战例+规则清单）
- 三天使图：Agent 在升级后的工具+知识辅助下，分件结果较 baseline（T6b v36：右头冠稀薄/逐星只能 6 簇）有可审查的改善证据
- 迭代档案：`experiments/sam-playbook-20261004/iter-N/` 每轮完整存档（会话/分享链接/Codex 审查/调整记录）
- **Codex 明确判定「满意」**（终轮审查结论原文留档）
