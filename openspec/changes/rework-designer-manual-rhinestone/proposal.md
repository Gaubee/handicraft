# Proposal: rework-designer-manual-rhinestone — 设计师工作台第二轮：手动排钻专注版

## Why

Owner 于 2026-09-21 亲自试用设计师工作台后的定向反馈（原话逐字落档）：

> 1. 没有正确使用水钻贴图
> 2. 贴图应该要配合一个 `backdrop-filter:shadow`，并且 hover、select 的时候，对应的 backdrop-filter 要发生改变来提供视觉反馈
> 3. 目前的鼠标操作逻辑很不舒服，你应该是没有正确参考 PS 的笔刷和钢笔的交互。特别是这种添加、删除的逻辑，应该参考钢笔的鼠标键盘协作方式。比如如何框选、如何多选，如果批量操作等等，如何旋转、如何改尺寸
>    说到改尺寸，这是最大的问题，排钻这里是一定要配置尺寸才能正确排钻的不是吗，你现在都没提供相应的配置支持。动态修改尺寸并不会影响布局，我们的布局需要按相对图片的像素或者说是相对位置来存储。所以如果改尺寸，相对应的结果是钻在原来的位置会放大缩小，仅此而已。所以动态修改尺寸是安全的。
> 4. 智能排布这个功能，应该基于选区来实现，所以你要做智能排布，首先要支持选区功能。但是目前我们的图层没有选区的概念，所以你目前做这个真的值得商榷。除非你能引入这个功能，但这个功能意味着和"路径"功能有关系，你得先引入路径功能，因为路径功能意味着要能编辑路径。所以我真不建议你在这个版本加入这个功能，你可以预留一个 change，后续再做。现在这个版本，应该专注于如果做好手动排钻工作
> 5. 相比于智能布局，现在更重要的是关于笔刷的设定，你需要设计一种类似 PS 的"笔刷流量"控制，说白了就是间距，基于你画过画安的面积来"落子"，注意我说的是面积不是距离。因为笔刷不是一个点（你现在就是在做一个点），而是一个图形，基于这个图形去扫画面，就可以实现相应的效果。要注意的是，落子的时候要尽量避免碰撞。

（注：原话中「画过画安的面积」按上下文取「画过画布的面积」。）

## What Changes

五条工作流（vision 9.2b 走查报告返回后，其问题清单作为补充证据并入 design）：

1. **水钻贴图渲染**：画布钻的渲染从几何符号改为 `.gemshape` 目录纹理资产贴图（gemCatalog 纹理真源）；每形预烘焙带阴影/高光的 sprite；hover/选中态通过 filter 变化（阴影加深/发光/描边）提供即时视觉反馈（Owner 的 `backdrop-filter: shadow` 意象在 canvas 语境的对应实现——`ctx.shadow*` 或预烘焙态帧）。
2. **交互对齐 PS（笔刷/钢笔参照系）**：添加/删除、框选、多选、批量操作、旋转、改尺寸的键鼠协作全面重审——以 PS 习惯为准绳（如钢笔式的确认/取消/回退协作、笔刷流的实时预览、选区操作的修饰键族）；尺寸配置的可发现性与动态修改安全性为核心验收——**尺寸动态修改绝不重排**：布局按相对参考图的像素/相对位置存储（核对并冻结现有 px 存储模型），改尺寸=原位放大缩小 sprite，仅此而已。
3. **笔刷流量（面积落子）**：笔刷从「点间隔落子」改为「图形扫面落子」——笔刷 footprint=钻形圆盘，扫过区域按面积覆盖落子（带宽=钻径的紧密/六方填充带，垂直于笔迹方向也填充），落子避碰（与既有钻与批内同判）。
4. **智能排布退役（本版本）**：UI 入口（DocBar 按钮/右键菜单项/命令）移除，专注手动排钻；7.1 钻数组 API（smartLayoutGemsFromImage 内核）保留为冻结资产供未来复用；预留 change `add-designer-selection-paths`（路径编辑 → 选区 → 基于选区的智能排布，本版本不实现）。
5. **vision 走查问题清单回修**：9.2b 走查报告的 P0/P1 项并入本 change 一并修复。

## Non-Goals

- 选区/路径功能（归 `add-designer-selection-paths`，本版本零实现）
- 基于选区的新版智能排布（同上）
- 移动端交互深化（8.x 已有降级面，走查问题另行处理）
- 排钻工作台（studio）侧任何改动
