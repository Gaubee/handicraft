# 排钻工作台五点优化 + 改名（improve-paving-workbench）

## Why

Owner 五点原话（2026-09-20，逐字落档；实现裁决见 design，均标注可推翻）：

1. 「图层现在只显示2个图层，这就不对的，我明明看到你可以选中部分的图片区块，但是结果就只显示成1个图层，我要的是每一个图片区块都是1个图层，就好比我在画布中选中的每个区块一样，它都应该是个图层。(我搞不懂你设计一个"移入图层"的设计，关键你只给了一个图层一那有什么意义呢)」
2. 「历史记录在撤回和前进时，列表数量不应发生改变，只能把聚焦的条目往回调。比方说现在有9条记录，撤销一步，只能把当前记录往后挪到后边那条记录上，总共9条记录是不会变的；只是说如果这时候强行去做一些修改，之前的记录会被覆盖掉。这个我不该解释那么多，你就参考PS的设计去做就好」
3. 「界面上有一些"建议 填充"，这种提示删掉，同时密度可以拉到0%」
4. 「我有点没搞懂你的"块列表"的设计是什么意思？」（Owner 自答于第 5 点：块 = 二级图层思路——独立「块列表」入口废除）
5. 「你是在图层一里面挂了一堆的二级图层来做管理。这个思路是好的，关键你没做彻底啊。那就是把我前面说的那个，改成`#No`这些都应该作为二级图层。在左侧的列表中能看到这些二级图层。另外一级图层还需要拖动排序、重命名。不过我发现移入图层的功能有BUG。并且移入图层这里没有正确同步绑定图层信息，始终显示"移入图层"」「因为是二级图层，所以排钻策略和基础规格这些，二级图层理论上可以独立微调，但是这种独立微调是有代价的，因为它脱离的一级图层的参数管理，那么就需要独立给它配置一个图层」

第 5 点「独立微调」的设计修订（Owner 原话，2026-09-20，经主会话冻结口径下发）：

> 「这里明确给出一个"继承"开关，开启就是跟随一级图层的配置，关闭就是可以自己进行微调，这样我可以随时切换是否继承」

另附主会话冻结裁决（可推翻，见 design §0）：画布⇄面板选中双向同步；拖动排序仅视觉序（层排序不改变几何与 BOM 顺序纪律保持）；移入图层修复（真实生效 + 标签同步当前绑定图层）；0% = 无钻合法状态走既有禁用口径；改名「排钻设计→排钻工作台」（代码面，TERMS/PRODUCT_MODEL 登记留主会话）。

## What Changes

- **二级图层树（点 1/4/5）**：左列图层面板改树状——一级图层行可折叠，展开显示成员块子行（`#No` 即二级图层；rest 兜底层下同样显示）；块归属真源仍是 `LayerRecord.blockIds`，二级为视图层派生。检查器「块列表」折叠组废除（功能并入树）。画布选中块 ⇄ 面板选中其二级图层行双向同步。
- **一级图层拖动排序 + 重命名（点 5）**：行拖动排序 = `layer.reorder` op（可撤销、随 layers[] 声明序入档）；联合计算/编号/BOM 顺序固定按层 id 稳定序——「层排序不改变几何与 BOM 顺序」纪律保持。重命名既有（双击/菜单），保持。
- **移入图层修复（点 5）**：移动块后新旧所属层标脏重算（现状缺标脏 = 功能性 BUG）；入口标签同步当前绑定（「移入图层 · 当前：图层N」）；菜单禁用态按真实归属判定。
- **块级「继承」开关（点 5 + 修订）**：每块显式开关——开 = 跟随一级图层（面板只读显示父层值 +「继承中」标记）；关 = 独立微调排钻策略 + 基础规格。关→开独立配置休眠保留（不清空），再关恢复；首次关闭以父层当前配置快照为起点。独立态块 = 隐式独立计算单元（复用 per-layer 计算管线，合成单元 `${layerId}#${blockId}`）。
- **历史 PS 游标模型（点 2）**：ops 数组 + 游标——undo/redo 仅移动游标（列表条目恒不变，游标后条目灰显只读）；仅游标非尾时新操作截断前向。fold/压实/序列化适配；跨重分块 undo 语义保持。
- **UI 清理 + 密度 0%（点 3）**：「建议 填充」类提示全删；块/层密度滑杆最小 0%（0 = 无钻合法状态，排除口径同禁用块——不参与排布/预估/统计，导出门既有规则）。
- **改名（代码面）**：排钻设计 → 排钻工作台（桌面 Tab、toast、EditView 引导、注释、测试断言全库 grep 改齐）；移动端 Tab「排钻」不变；TERMS.md / PRODUCT_MODEL.md 不动（登记留主会话，其契约测试随文档保持）。
