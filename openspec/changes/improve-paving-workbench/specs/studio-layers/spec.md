# 排钻工作台能力（studio-layers）Delta — improve-paving-workbench

## ADDED Requirements

### Requirement: 二级图层树与双向选中
排钻工作台左列图层面板 MUST 呈现树状结构：一级图层行（可折叠）展开显示其成员块子行（`#No` 区块即二级图层，含色点、实际钻数与独立徽标）；rest 兜底层下的块 MUST 同样显示；区块归属真源 MUST 保持为 `LayerRecord.blockIds`（二级为视图层派生）。画布选中区块 MUST 等价于选中其二级图层行，面板选中二级图层行 MUST 等价于选中该区块（双向同步，父层自动展开）；独立于图层树的「块列表」入口 MUST 废除（职能并入树）。一级图层 MUST 支持行拖动排序与双击重命名：拖动排序 MUST 记为可撤销的 `layer.reorder` 操作且随层声明序入档；联合视图的层序（编号/BOM/导出顺序）MUST 固定按层 id 稳定序——拖动排序 MUST NOT 改变几何与 BOM 顺序。「移入图层」MUST 真实生效（移动后新旧所属层均进入重算）且入口标签 MUST 同步显示当前绑定图层（如「移入图层 · 当前：图层2」），菜单中当前所属层 MUST 禁用。
#### Scenario: 画布选块即选层树子行
- **WHEN** 用户在画布点选某区块
- **THEN** 左列树中该区块所在一级层自动展开、对应二级子行高亮，所属一级层进入选择集
#### Scenario: 拖动排序不改 BOM
- **WHEN** 用户将「图层 3」拖到「图层 1」之前并保存导出
- **THEN** 面板顺序变为新序，但联合钻编号、BOM 与导出内容与拖动前逐项一致
#### Scenario: 移入图层生效可见
- **WHEN** 用户将某区块从图层 A 移入图层 B
- **THEN** A 与 B 均进入重算，画布钻位与统计按新归属更新，入口标签显示「当前：图层 B」

### Requirement: PS 游标历史
排钻工作台历史 MUST 为 ops 数组 + 游标模型：撤销/重做 MUST 仅移动游标——历史列表条目数量与内容 MUST NOT 因撤销/重做而变化，游标之后的条目 MUST 灰显只读；仅当游标非尾时执行新操作 MUST 截断前向条目（被覆盖即消失）；同组合并滑杆提交、100 组压实（记边界与 state hash）、跨重分块撤销（引擎确定性重建旧块归属）、失效操作只读诊断、历史栈永不序列化、⌘Z/⇧⌘Z 与面板按钮同源等既有语义 MUST 全部保持。
#### Scenario: 九条记录撤销不缩表
- **WHEN** 历史有 9 条记录且用户撤销一步
- **THEN** 列表仍为 9 条，当前态行移至第 8 条，第 9 条灰显只读；重做后第 9 条恢复
#### Scenario: 撤销后强改覆盖前向
- **WHEN** 用户撤销两步后执行新操作
- **THEN** 前向两条被截断移除，列表 = 8 条中前 7 条 + 新条目，重做不可用

### Requirement: 块级继承开关与独立配置
每个二级图层（区块）MUST 提供显式「继承」开关：开启 = 跟随一级图层配置（面板只读显示父层值并标注「继承中」）；关闭 = 独立微调排钻策略与基础规格。关闭时若无休眠配置 MUST 以父层当前配置快照为独立配置起点；再次关闭 MUST 恢复此前休眠的微调值（关→开 MUST NOT 清空独立配置数据）。计算语义：继承态区块 MUST 随父层配置变化重算；独立态区块 MUST NOT 随父层配置变化（以自身配置作为隐式独立计算单元参与计算管线，其自定义规格解析失败 MUST 只隔离该区块）。独立配置数据在当前工程文件格式下为会话态（保存/重开回落继承），该降级 MUST 在 change 文档登记为后续格式升级项。
#### Scenario: 继承块随父层变
- **WHEN** 某区块开关开启且用户修改其父层策略
- **THEN** 该区块按父层新策略重算
#### Scenario: 独立块不随父层变
- **WHEN** 某区块开关关闭（独立配置策略 X）且用户修改其父层策略为 Y
- **THEN** 该区块仍按策略 X 计算不受影响
#### Scenario: 开关休眠恢复
- **WHEN** 用户关闭开关微调后重新开启再关闭
- **THEN** 区块先恢复跟随父层，再关闭时回到此前微调值（不重摄父层快照）

### Requirement: 密度零值与提示清理
区块与层级密度滑杆最小值 MUST 为 0%：生效密度为 0 的区块 MUST 视为无钻合法状态并按既有禁用口径排除（不参与排布输入、预估与统计，导出门按既有规则处理）；引擎与工程文件值域 (0,1] MUST NOT 被触破（0 密度不进入计算输入与序列化值）。界面上「建议 填充」类推断提示 MUST 删除。
#### Scenario: 密度 0 无钻
- **WHEN** 用户将某区块密度拖至 0%
- **THEN** 该区块预估与实排为 0 钻、统计合计相应减少，保存工程不报值域错误
#### Scenario: 建议提示清零
- **WHEN** 检查排钻工作台全部面板文案
- **THEN** 不存在「建议 填充」类推断提示徽标（类型值显示与注释措辞不在范围）

### Requirement: 排钻工作台命名
代码与界面文案中「排钻设计」MUST 更名为「排钻工作台」：桌面 Tab、交接 toast（「已送入排钻工作台」「与排钻工作台参数隔离」）、专家工作台空态引导（「去排钻工作台送精修」）、注释与测试断言全库一致；移动端 Tab「排钻」MUST 保持不变；术语表与产品模型文档的登记不在本要求范围。
#### Scenario: 全库改名收据
- **WHEN** 对仓库源码与测试执行「排钻设计」grep
- **THEN** 除术语表/产品模型文档及其契约测试（留待文档域变更）外命中清零，移动端「排钻」Tab 保留
