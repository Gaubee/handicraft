# 贴钻工作台（rhinestone-studio）开发计划

## 目标

在 `/Users/kzf/Pictures/贴钻/rhinestone-studio/` 新建一个纯前端应用（Svelte 5 + shadcn-svelte + Vite 8 + Tailwind v4），含两个模块：

- **模块 A「提示词实验室」**：上传原图 → 编辑多组提示词变体 → 每组生成 N 张（默认 2）gpt-image-2.5「贴钻层数字油画」候选 → 分组画廊 + 与原图叠加预览
- **模块 B「转化工作台」**：数字油画 → 自动分块（图块）→ 每块密度可调 → 4 种排钻算法同屏对比（人类视觉裁决）→ 导出 SVG / BOM

以 OpenSpec + 敏捷工作流（COMPACT-WORKFLOW）推进，Codex 不参与，开发与评审均由 zcode 子代理执行（后台运行）。

## 架构总览

```text
[模块 A 提示词实验室]                    [模块 B 转化工作台]
原图上传 → 提示词变体组(可编辑)           数字油画(来自A或上传)
   → gpt-image-2.5 (BYOK 直连)             → 分块: 量化(k色)+连通域 → Block[]
   → 每变体×N候选 并发生成                  → 每块: 类型推断(细→链/块→填充) + 密度滑杆
   → 分组画廊 + 叠加/并排预览               → 4 算法并行渲染对比 → 人工挑稿
   → 选中 → 送转化 ──────────────→         → 颜色映射(Lab ΔE→钻色) → SVG/BOM 导出
```

## 关键设计决策

**1. BYOK 纯前端、零后端**（整体移植 openai-image-webui 模式）：
- baseUrl 自由填写（官方/中转站）、key 存 localStorage、裸 fetch（无 SDK）
- `POST {base}/images/generations`（JSON）/ `POST {base}/images/edits`（multipart，有参考图自动切换）
- 永远发 `n:1`，多候选 = 客户端并发多个独立请求（单图可重试）
- Advanced JSON 逃生舱透传 `background: transparent`、`quality`、`seed` 等
- 响应同时兼容 `data[0].url` 与 `data[0].b64_json`；FormData 不手动设 Content-Type
- 上传预处理：MIME 白名单、>2048px 自动降采样、debug 对象全量记录
- 持久化：IndexedDB 存图 + localStorage 存任务/设置（三级配额降级）

**2. 转化引擎为纯 TS 零依赖模块**（`src/lib/engine/`，不 import Svelte，vitest 全覆盖）：
- **分块**：Lab 空间 k-means 量化（k≈6-10）→ 逐色掩码 → 连通域 → Block{id, color, area, bbox, 距离变换宽度统计}；细块（宽度<阈值）标 linear、小连通域标 element
- **4 种排布算法**（统一策略接口 `layout(block, density, grid) → Gem[]`）：
  - S1 六方定距网格 + blue-noise 抽稀（density=保留概率，格位不变）
  - S2 六方网格 pitch 调制（density→间距缩放，晶格永远完美）
  - S3 Poisson disk 变径散布（Bridson，density→半径）
  - S4 语义混合（细块走 Zhang-Suen 骨架+等弧长链排，宽块走六方填充）
- **密度语义**（用户核心需求）：每块独立滑杆 0-100%；三种映射均保证钻数 ∝ density 单调；实时显示每块预估钻数
- **颜色映射**：块色 → Lab ΔE 最近邻 → 内置起步色板（红/金/象牙/橄榄/黑，可编辑增删）
- **校验导出**：spatial hash 碰撞检查、最小间距、分层 SVG（按色分组圆点）、BOM CSV（色×尺寸×数量）、PNG 渲染
- SS 尺寸表 SS6-SS34 内置（直径/pitch 查表）

**3. 提示词变体默认包**（初始 5 组 × 2 候选 = 10 张，基于样本实证规则）：变体覆盖"严格扁平+硬删氛围层 / 保留部分渐变 / 描边强调 / 浆果逐颗圆点 / 极简高光"等取向，全部可编辑、可增删。

**4. 界面**：单页两视图切换（实验室/工作台），中文 UI，shadcn-svelte 组件 + 画布用原生 canvas/SVG 渲染；预览三模式（纯钻点/叠数字油画/叠原图）+ 透明度滑杆。

## 执行步骤（OpenSpec 敏捷工作流）

1. **P0 开局**：`npx openspec init`（CLI 不可用则手工按规范搭 openspec/ 目录）→ 撰写 change 文档（proposal/design/tasks/spec deltas，design.md 冻结引擎 API 契约与密度语义）→ 子代理①脚手架（Vite 8 + Svelte 5 + shadcn-svelte + Tailwind v4 + vitest），验证 dev server 可跑（Vite 8 若与 shadcn-svelte CLI 不兼容，降级 Vite 7 并记录）
2. **P1 并行开发**（后台子代理，不同目录无竞写）：子代理②转化引擎 + vitest（几何不变量：最小间距、无重叠、钻数随密度单调）；子代理③模块 A UI（API 客户端 + 提示词变体 + 分组画廊 + 叠加预览 + 持久化）
3. **P2**：子代理④模块 B UI（分块视图 + 每块控制 + 四算法对比网格 + 导出），按 design.md 契约对接引擎
4. **P3 评审闭环**：评审子代理（按 Codex 评审标准执行：阻塞问题/可验证修复建议/质量评价/0-10 综合评分，基于真实 diff 与测试结果，不复述自评）→ 修复迭代 → vision 子代理对真实运行界面截图走查 → 用户视觉验收（重点：四算法效果对比 + 密度控制手感）
5. **P4 收尾**：归档 openspec change → `git init` + 首次提交（工作区无远程，push 不适用）→ 汇总报告

## 风险与对策

- **Vite 8 (Rolldown) 新**：脚手架阶段第一时间验证，不兼容则降 Vite 7（已确认 shadcn-svelte 与 Svelte 5/Tailwind v4 完全兼容，Vite 版本不直接影响组件库）
- **gpt-image-2.5 端点差异**：模型名自由文本 + Advanced JSON 逃生舱兜底；沿用参考项目 debug 记录便于排查中转站
- **CORS**：BYOK 直连的已知成本（参考项目 README 同款声明），用户现有中转站已验证可用
- **算法效果需人类裁决**：这正是产品形态——多算法同屏对比由用户挑稿，不追求单一"正确"答案
