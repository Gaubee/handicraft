## 二、我能诚实给你的：抠图方法论框架（「我会怎么做」，不是「我做过了什么」）

你的六个关注点，我逐条映射到这套框架上——等真正的分割跑完，你看到的指令就是这个形态：

1. **总体顺序**：先 `scene.analyze` 出全图元素清单（语义元素 + 像素包围盒 + 英文 hint），再由 `subject.segment` 按**父先子后**的拓扑序迭代抠图——先大域（主体整体）后细部（部位 refinement）。原因是硬性的：细部 hint 只在父层掩膜范围内才枚举得到，父层没抠出来，子层无从下手。
2. **参考图层 vs 原图**：photographic 类图在 S2 完成时自动生成参考图层，分件环节服务端**单源**自动以它为送桥输入（结构真源），原图保留色彩细节——调用方无需改任何参数，出参 `segmentImage.source` 会标注用的是哪张。
3. **数词禁令（你提纲里「三天使/六颗星」对应的核心规则）**：「三位天使」「six stars」永远不进提示词——量化词会触发实例合并（issue #586 + 上面那条战例）。同款多件用 `instances: 'all'` 逐个成层，**计数永远在掩膜层做**；且 instances 枚举只在该节点掩膜范围内进行，枚举不到先查域再查分。
4. **部位措辞**：单数光杆名词 + ≤2 视觉属性（`face` / `golden hair` / `flower wreath` / `robe` / `wing`）；特称失败回退泛称（cherub→angel→person）；同一提示词绝不重发，失败必换措辞。
5. **box 框选 vs 语义词**：语义词穷尽、实体没有独立名字时用纯正框兜底（框住即抠，不赌语义命中）；掩膜泄漏（`mask-parent-iou` / `mask-suspicious-aspect`）用 `excludeBox` 做确定性像素减法——**否定词不是排除算子**，「不要背景」这类写法无效。
6. **参数纪律**：`precision {confThreshold, maskMaxSide}` 有配置缺省（confThreshold 常见 0.4）；只在看到掩膜质量差（空膜/条带泄漏/细节收缩）时才覆写，且**必须实际携带参数**——文案里宣称「已降阈值」无效，以 wire 回执为准。这条也是知识库里的两条铁律之一。
